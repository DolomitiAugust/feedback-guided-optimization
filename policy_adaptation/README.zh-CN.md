# 低秩策略适配

[English](README.md) / [简体中文](README.zh-CN.md)

本模块包含手写 LoRA 层、行为测试和固定 OpenRLHF 版本的 PPO 流程。基础模型为 `Qwen/Qwen2.5-0.5B`。LoRA 冻结原权重，只学习两个小矩阵的乘积；PPO 根据正确答案奖励更新策略，同时用固定参考策略约束偏离程度。Critic 则学习估计回报，帮助计算优势。

## 真实结果与边界

A10/BF16 实验处理 512 个训练提示，共 32 个 rollout 批次；每批 16 题。在相同的 128 道开发验证题上，贪心解码的首行整数准确率由 117/128 提升为 122/128，增加 3.90625 个百分点。这是五道由错变对、没有由对变错的结果。它不等于通用推理能力提升，也不代表多个随机种子的平均结果。

Actor 与 Critic 适配器均保存。Actor 在 GPU 上实际重载并通过前向和生成检查；Critic 只检查了权重有限且非零，没有单独重载。没有完整的 PPO 优化器恢复检查点。更早的 T4/FP32 实验虽然完成 32 批训练循环，却在最终保存时报错；该记录保留在 `logs/observed_attempt/`，不能把其 118/128 基线与新 A10 的结果混用。

## 文件说明

- `lora_training.py`：低秩线性层、嵌套投影替换、可训练参数统计和合并。直接运行示例会下载模型；导入和测试不会下载。
- `train_ppo_lora.py`：默认只打印配置，显式加 `--run` 才训练；拒绝覆盖已有非空输出。
- `ppo_reward.py`：只给模型回答的第一行整数评分，提示里的数字不会获得奖励。
- `ppo_reward_server.py`：把相同规则通过仅本机访问的 HTTP 接口提供给框架。
- `prepare_ppo_data.py`：固定随机种子生成互不重叠的 512/128 划分。
- `evaluate_ppo.py`：使用相同的提示、生成长度和评分规则评估基础模型及适配模型。
- `patch_openrlhf.py`、`optional_flash_imports.py`：对固定上游版本实施经检查的兼容性修改。
- `results/`：成功实验的标量、逐题回答、配置和模型适配器；`data/` 是原始训练及开发验证题。

## 复现方式

从仓库根目录运行 `python tests/test_policy.py` 可做九项 CPU 行为检查，先按英文说明安装 `requirements_lora.txt`。测试覆盖初始等价、合并等价、真实梯度更新、冻结原权重、递归替换、边界配置、数据划分和奖励接口。

完整 GPU 命令见 [English README](README.md#gpu-reproduction)。需要单独的 Linux/Python 3.10/CUDA 环境。历史成功路线使用 eager 注意力并关闭 packing/ring；没有安装 FlashAttention，但框架声明中仍保留该缺失项。安装脚本会验证这唯一例外和实际 CUDA 优化器更新，不能把依赖声明通过当作完成训练。

先运行 `python prepare_cloud_model.py`，把模型固定到报告使用的修订 `060db6499f32faf8b98477b0a26969ef7d8b9987`，后续统一使用 `--pretrain .cloud_model`。不要直接依赖远端默认版本。开始前确认 `cloud_model.json` 的精度为 `bf16`；FP32 运行应单列为另一条记录。

运行完整实验前，先做独立的 16 题保存与重载检查，再从原基础模型开始 512 题训练。保存新输出时使用新目录，避免覆盖本仓库记录。训练前后的评估必须采用相同 BF16 精度与相同数据。

三份绘图脚本只读取已有结果，不重新训练；圆点和方格都对应真实保存记录。适配器配置中的云端绝对路径已改成公开模型 ID，权重本身没有修改。
